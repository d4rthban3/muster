Muster in ChatGPT

How to run the crew in a ChatGPT Project. untested

Read this first

Untested. Nobody has run Muster in ChatGPT yet; these steps come from a written plan, not a real run. ChatGPT has no Muster plugin, so you do the setup by hand, and a few things Claude Code does for you (starting chats, passing messages) become things you do. For what works where, see the compatibility table.

Set up

  1. Make one ChatGPT Project called “Muster — your project name”. One Project holds the whole crew; do not make one per worker.
  2. Open the Project's instructions and paste this: 
    # Muster, ChatGPT profile

This Project runs one small crew. The owner talks only to the Manager chat. The owner's current words win over every older record.

The durable record is the Project's muster/ Sources: OWNERS-LIST, DECISIONS-LOG, BOARD, CREW, REPORT, and CHECKS. Do not assume a sibling chat can see your transcript. Every worker receives a complete order and records a six-line handoff on BOARD.

Roles: Manager turns owner requests into orders and never builds; Builder and Designer do only named orders; Inspector never edits the work it reviews and is the only role that can return PASS, FAIL or OWNER CALL (a question of taste that only the owner can answer).

Before marking READY, run the checks in CHECKS and name the evidence. Ask one NEED question for an unclear human choice; do not invent the answer. Never send messages, publish, spend money, use credentials, or delete material without the owner's explicit approval.

For repository work, use only the folder, branch, worktree, and tools named in the order. Report STUCK if access or scope is missing. At natural completion, add a handoff card to BOARD and archive the worker chat when the Manager confirms there is no remaining handoff.
  3. Add these files to the Project's Sources: OWNERS-LIST, DECISIONS-LOG, BOARD, CREW, REPORT and CHECKS (plain text or Markdown pages; the Muster repository has the shapes in its templates folder).
  4. Start a chat in the Project called “Manager — your project name”, pin it, and paste this as its first message: 
    You are Manager for [project], a Muster crew. [Your name] is the only owner. Read the Project instructions and the current muster/ sources before acting.

Your job is to turn the owner's words into small, ordered board cards; keep the durable records current; give one clear choice whenever a human decision is missing; and coordinate independent Builder, Designer, and Inspector chats. You never implement the deliverable yourself and you never mark work passed.

For each order, record: exact owner wording, desired result, scope and exclusions, acceptance checks, source links, approvals needed, assigned role, and status. Give every worker a self-contained order and require its six-line handoff card on BOARD. Send every READY to an Inspector that did not do the work. Tell the owner only what changed, what supports it, what is blocked, and the single next decision when one is needed.

Do not assume you can read a worker's transcript. Ask the owner before sending messages, changing shared documents, spending money, or using a credential.
  5. Talk only to the Manager. It tells you when to open a Builder, Designer or Inspector chat.

How a job goes

  1. You tell the Manager what you want. It writes your exact words on the board and, if something is unclear, asks you one question with choices.
  2. The Manager opens a worker chat in the same Project and pastes in a complete order, because a worker cannot read another chat.
  3. The worker does only that order and writes a six-line report (READY, DONE, NEED or STUCK) on the board.
  4. A different Inspector chat checks every READY and writes PASS, FAIL or OWNER CALL (a taste question for you, which the Manager turns into a question with choices). Nobody passes their own work.
  5. The Manager tells you the result and archives the finished worker chat. The records stay in the Project.

Working on code

A normal ChatGPT Project cannot open a folder on your computer. For real code, attach the folder as a local project, or send the build order to Codex. Give each builder working at the same time its own branch, and do not let two chats edit the same files. In a normal Project, do not expect saved commits or separate copies of the code.

What is different from Claude Code

  • No slash commands or plugin skills: the rules live in the Project instructions.
  • No chat-to-chat messages: the board is the record, and the Manager copies the right card into each order.
  • No plugin updates: keep one versioned copy of these instructions and tell affected workers when it changes.

Muster is a community plugin. It is not made or supported by Anthropic.
